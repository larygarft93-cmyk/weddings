# Wedding Invitation Project Documentation

## 1. Что это за проект

Это статический сайт-приглашение на свадьбу, собранный на HTML + CSS + JavaScript без сборки и фреймворков.

Основная страница: [wedding-invitation/index.html](index.html)

Проект состоит из двух основных частей:

- [wedding-invitation/index.html](index.html) — разметка страницы и подключение скриптов/стилей
- [wedding-invitation/css/styles.css](css/styles.css) — визуальный дизайн, анимации, слои, оформление конверта, i18n и общий стиль сайта
- [wedding-invitation/js](js) — JavaScript-модули для логики поведения сайта
- [kyrgyz-wedding/assets](../kyrgyz-wedding/assets) — фото, иконки, орнаменты, музыка, фоновые изображения

## 2. Как проект запускается

Так как это статический сайт, запуск очень простой:

```bash
cd /home/lil/stitch_kyrgyz_wedding_digital_invitation
python3 -m http.server 8000 --directory .
```

После этого открыть:

```text
http://localhost:8000/wedding-invitation/
```

Проверка запуска:

- при обращении к адресу есть ответ HTTP 200 OK
- страница отдаётся как обычный HTML
- проект не требует npm, сборки или зависимостей

## 4. Как устроена страница

### 4.1 Основной HTML

Файл [wedding-invitation/index.html](index.html) содержит:

- выбор языка
- стартовый слой с конвертом
- основной контент сайта
- секции:
  - hero
  - welcome story
  - countdown
  - story/history
  - program timeline
  - venue info
  - gallery
  - RSVP form
  - footer
- модальное окно выбора карты

### 4.2 Последовательность экранов

Логика стартового сценария полностью описана в [wedding-invitation/css/styles.css](css/styles.css) и [wedding-invitation/js/envelope.js](js/envelope.js):

1. пользователь видит выбор языка
2. после выбора языка появляется слой-конверт
3. после клика по печати конверта открывается основной сайт
4. при повторном входе система может сразу показать сайт, если сохранён флаг посещения

Это сделано для красивого onboarding и демо-сценария при первом посещении.

## 5. Где и что менять

### 5.1 Изменение текста и данных свадьбы

Главные места редактирования:

- [wedding-invitation/index.html](index.html) — практически весь текст страницы, включая:
  - имена пары

  - описание секций
  - текст RSVP
  - кнопки и лейблы
  - текст на русском/кыргызском

Сами строки обычно выглядят так:

```html
<p
  data-kg="Сизди үйлөнүү тоюбузга чакырабыз"
  data-ru="Приглашаем вас на нашу свадьбу"
>
  Сизди үйлөнүү тоюбузга чакырабыз
</p>
```

Это означает:

- `data-kg` — текст на кыргызском
- `data-ru` — текст на русском
- обычный текст внутри элемента — текущий текст по умолчанию

## 6. Что делает каждая JS-файл

### [wedding-invitation/js/state.js](js/state.js)

Ядро состояния сайта. Создаёт объект `window.WeddingSite` и хранит:

- выбранный язык
- данные гостя из query-параметра `?guest=`
- ссылки на вспомогательные функции (`setLanguage`, `renderMiniCalendar`)

### [wedding-invitation/js/language.js](js/language.js)

Ответственен за:

- переключение между `kg` и `ru`
- сохранение языка в `localStorage`
- перевод всех `[data-kg]` / `[data-ru]` элементов
- обновление кнопки переключения языка

### [wedding-invitation/js/envelope.js](js/envelope.js)

Отвечает за сценарий приветствия:

- отображение выбора языка
- показ конверта
- открытие конверта по кнопке
- переключение в основной сайт
- сброс welcome flow через `?resetWelcome=1`

### [wedding-invitation/js/countdown.js](js/countdown.js)

Счётчик до свадьбы:

- дата: 19 сентября 2026, 17:30
- обновляется каждую секунду
- показывает дни, часы, минуты

### [wedding-invitation/js/calendar.js](js/calendar.js)

Отрисовывает мини-календарь с выделенным днём свадьбы.

### [wedding-invitation/js/gallery.js](js/gallery.js)

- загружает список фото
- генерирует карточки галереи
- подключает горизонтальную анимацию GSAP + ScrollTrigger

### [wedding-invitation/js/venue-map.js](js/venue-map.js)

- при нажатии открывает выбор карты
- даёт выбор между Google Maps и 2GIS
- строит поисковую ссылку по адресу

### [wedding-invitation/js/rsvp.js](js/rsvp.js)

- обрабатывает форму RSVP
- читает имя гостя
- проверяет выбор присутствия
- определяет, с кем идёт гость
- показывает alert с итогом

### [wedding-invitation/js/audio.js](js/audio.js)

- включает/выключает фоновую музыку
- управляет состоянием кнопки
- работает с `<audio id="bg-music">`

### [wedding-invitation/js/reveal.js](js/reveal.js)

Подключает анимацию появления элементов при скролле через `IntersectionObserver`.

### [wedding-invitation/js/navigation.js](js/navigation.js)

Управляет кнопкой "Назад" и клавишами Escape/Backspace.

### [wedding-invitation/js/ics.js](js/ics.js)

Создаёт файл `wedding.ics` при нажатии на кнопку "Добавить в календарь".

## 7. Как работает язык и i18n

В проекте не используется отдельный конфиг локализации. Вместо этого используется простой и практичный подход:

- на каждом текстовом элементе есть `data-kg` и `data-ru`
- `language.js` меняет `innerHTML` в зависимости от текущего языка
- сохраняет выбор в `localStorage`

Пример:

```html
<p data-kg="Күнү" data-ru="Дата">Күнү</p>
```

Если надо добавить новый язык — это потребует:

- добавления нового атрибута
- доработки логики в `language.js`
- обновления выбора языка в UI

## 8. Как работает стартовый сценарий

Важный момент: сайт имеет не просто обычное отображение, а последовательность экранов.

Порядок инициализации:

1. `state.js` создаёт `WeddingSite`
2. `calendar.js` создаёт функцию `renderMiniCalendar`
3. `language.js` создаёт `setLanguage`
4. `envelope.js` решает, какой экран показывать и отрабатывает welcome flow
5. остальные модули инициализируются после

Это важное правило: подключение скриптов в HTML идёт по строгому порядку, потому что они зависят друг от друга через `window.WeddingSite`.

## 9. Прочие важные детали

### 9.1 Используются внешние библиотеки

- Tailwind CDN
- GSAP
- ScrollTrigger
- Google Fonts
- Material Symbols

Это означает, что сайт работает корректно только при наличии интернет-соединения для загрузки стилей/шрифтов/JS библиотек.

### 9.2 Без сервера открывать напрямую можно, но есть риски

Локально открыть `index.html` напрямую можно, но некоторые функции могут вести себя нестабильно из-за:

- относительных путей к музыке/фото
- ограничения CORS для некоторых технологий
- порядка включения скриптов

Лучше всегда использовать локальный сервер через `python3 -m http.server`.

### 9.3 Состояние и параметры URL

Есть поддержка ручного сброса welcome flow:

```text
/?resetWelcome=1
```

Это чистит `localStorage` и делает показ приветствия заново.

Существует также параметр `?guest=Имя` — он используется для персонализации приветствия.

## 11. Потенциальные проблемы и улучшения

### 11.1 Проблема: много текста жёстко вшито в HTML

Плюсы:

- быстрый старт
- простая правка

Минусы:

- трудно поддерживать много языков
- сложно масштабировать
- легко забыть синхронизировать текст в нескольких местах

Рекомендация:

- вынести данные свадьбы в отдельный JSON или конфиг-файл
- хранить тексты в одном справочнике
- генерировать DOM из данных

### 11.2 Проблема: дата и адрес размазаны по нескольким файлам

Сейчас дата и адрес повторяются в нескольких местах.

Рекомендация:

- вынести в единый объект `weddingConfig`
- использовать этот объект в JS
- при необходимости обновлять только одно место

### 11.3 Проблема: часть логики находится в inline-скриптах и разрозненных модулях

Хотя структура уже нормальная, она ещё не идеальна для масштабирования.

Рекомендация:

- использовать ES-модули (`type="module"`)
- иметь единый конфиг
- централизовать текст и данные

### 11.4 Проблема: музыка может не запускаться автоматически

В некоторых браузерах автозапуск медиаконтента ограничен.

Рекомендация:

- запускать музыку только после пользовательского клика
- дать явную визуальную индикацию состояния

### 11.5 Проблема: личные данные в форме не отправляются

Сейчас RSVP обрабатывает форму через `alert()`, а не через серверную отправку.

Рекомендация:

- подключить backend or Telegram/Email webhook
- хранить подтверждения в таблице/Google Forms/CRM
